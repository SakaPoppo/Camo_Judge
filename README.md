# Camo_（仮称）

> 背景画像と迷彩柄を比較し、「色彩的な類似性」と「人間の見つけにくさ」を別々に可視化する、サバイバルゲーム向け画像解析・視覚実験Webアプリ。

**ステータス：企画・要件定義（Draft v0.1 / 2026-11-12）**

## 1. コンセプト

森林・草地・落葉地・岩場などの背景画像と複数の迷彩柄を比較する。画像に迷彩柄を適用した人型シルエットを合成し、見た目の比較に加えて、画像処理による色彩分析と、クイズ参加者の検出結果を記録・集計する。

このアプリでは、迷彩の効果を単一の「正解」で断定しない。**色が似ていることと、人間が発見しにくいことは異なる指標**として扱う。

### 想定ユーザー

- サバイバルゲーム愛好者：フィールドの背景と迷彩柄を比較したい人
- 迷彩・衣類に興味がある人：色彩構成や模様の違いを可視化したい人
- 画像解析に興味がある人：視覚データと人間の回答の関係を探りたい人

### 解決したい課題

- 迷彩柄が「森林向け」「砂漠向け」などと呼ばれていても、具体的な写真の背景でどう見えるか分かりにくい。
- 色の一致度と視認性の違いを比較できるツールが少ない。
- 手持ちの迷彩服の色構成を数値化して比較する手段がない。

## 2. 迷彩の評価方針

迷彩には少なくとも次の2つの主要な視覚的原理がある。

1. **背景への同化（Background Matching）**：色相、明度、色の割合、模様の特徴が背景に近い。
2. **輪郭の分断（Disruptive Coloration）**：コントラストや模様の境界により、人型の輪郭を認識しにくくする。

用途は「地形カテゴリ」だけで決めず、実際の背景、季節、植生、撮影条件、見かけ上の対象サイズで変わると考える。

### 評価軸

| 軸 | 指標 | 初期実装 | 注意点 |
| --- | --- | --- | --- |
| 色彩類似度 | 色分布の近さ、主要色の比率、明度差 | Python画像処理 | 高い値でも発見されにくいとは限らない |
| 人間による視認性 | 発見率、発見までの時間、位置クリックの正誤 | クイズ回答の集計 | 表示条件・参加者・画像難易度に左右される |
| 模様・輪郭（拡張） | 模様の大きさ、局所コントラスト、輪郭周辺の特徴量 | 後続開発 | 人間の結果との検証が必要 |

**重要：** MVPの「色彩類似度」は画像同士の比較用指標であり、現実の隠蔽性能を示す認証値ではない。検出率の予測は十分なデータ収集・検証ができるまで提供しない。

## 3. 主要機能

### F1. 背景画像×迷彩シミュレーター（最優先）

- サンプル背景の選択、またはユーザー画像のアップロード
- 背景の種別・季節の任意登録（例：森林、草地、落葉地、岩場）
- 登録済みの迷彩柄の選択・切り替え
- 人型シルエットに迷彩柄を適用して背景へ重ねる
- シルエットの位置、拡大縮小、向き（必要であれば回転）を操作
- 同一背景・同一位置・同一サイズで複数柄を比較
- 比較画像の保存（画像の利用条件を満たす場合）

**初期の妥協点：** 合成は2Dの人型シルエットと迷彩テクスチャで行い、実写の人物写真に自動着せ替えする機能は後回しにする。合成画像は実写での見え方を完全には再現しない。

### F2. 色彩分析・可視化

- 迷彩柄と背景の主要色（例：上位5色）と構成比の表示
- 色のヒストグラムと明るさ（明度）の比較
- 色彩類似度の算出と比較表示
- 背景全体ではなく、配置位置の近傍領域を対象にできる仕組み
- 算出方法と「推定指標であること」の明示

候補となる実装方法：sRGB → CIELAB変換、KMeansによる代表色抽出、色ヒストグラムの距離比較（例：Hellinger距離）。必要に応じてΔE（色差）も補助指標に使う。代表色は撮影条件に影響される。

### F3. 迷彩図鑑

- 迷彩名、参考画像、主要色と比率
- 一般的に想定される環境カテゴリ（**用途ラベルであり性能保証ではない**）
- 各背景との分析履歴や比較結果
- 登録画像の出典・利用許諾の管理

### F4. 発見クイズ（人間の目による評価）

- 背景画像に人型シルエットを1体合成し、一定時間表示
- 参加者が人型を見つけたらクリック／タップ
- 正答位置、発見可否、発見時間を記録
- 順序・配置・柄をランダム化し、同条件で比較
- 一定数集まったデータを「見つかりやすさ」として集計
- 回答結果は統計集計に利用することを事前に説明する

**実験設計上の注意：** 同一背景の反復提示による学習効果、画面サイズ、明るさ、対象の大きさ、配置の偏りを管理する。未発見・誤クリックと発見成功を区別する。

### F5. 手持ちの迷彩服の登録

- 迷彩服の写真をアップロード
- 柄の写った領域をユーザーがトリミング
- 主要色と構成比を抽出
- 登録済み背景との色彩比較
- 将来的に自動切り抜き・照明補正を追加

**撮影の注意：** 日光・室内照明・ホワイトバランス・影・生地のしわによって色が変わる。初期は「写真に写った色の分析」であって、生地固有の色を厳密に測定するものではない。

## 4. MVPに入れる範囲

- [ ] 代表的な背景・迷彩柄のサンプルデータを準備
- [ ] 背景画像と迷彩柄を選び、人型シルエットを配置する
- [ ] 位置とサイズを調節し、迷彩柄を切り替えて比較する
- [ ] 主要色とその割合、色彩類似度を表示する
- [ ] 自分の迷彩服写真をアップロードして色彩を分析する（手動トリミング可）
- [ ] シンプルな発見クイズを実装する
- [ ] 回答の発見成功・失敗と発見時間を保存する

### MVPでは行わないこと

- 自動で「最も隠れられる迷彩」を保証する判定
- 衛星写真や地名だけでの現場評価
- 実写人物への高精度な自動着せ替え
- 人間の視認性を予測する学習済みモデルの公開（データ蓄積後に検討）
- 動画や移動時の視認性評価

## 5. 機械学習の導入計画

### Phase A：画像処理＋探索的な機械学習

- OpenCV：画像の切り抜き、色空間変換、ヒストグラム比較
- scikit-learn の KMeans：代表色と構成比の抽出（教師なし学習）
- 複数の背景・迷彩の色彩特徴を記録し、比較可能にする

### Phase B：人間の回答を教師データとして収集

1. 背景×迷彩×配置条件の画像を生成する
2. 参加者が見つけられたか、何秒かかったかを記録する
3. 画像の色彩・明度・模様の特徴量と紐付ける
4. 背景や参加者単位で学習・検証データを分離する

### Phase C：人間の視認性の予測（将来）

- 目的変数の候補：所定時間内の発見成功（0/1）
- 特徴量の候補：色彩距離、明度差、局所コントラスト、模様の空間的特徴、対象サイズ
- 最初のモデル候補：LogisticRegression / RandomForest / 勾配ブースティング
- 指標：ROC-AUC、適合率・再現率、確率の校正、未使用背景での性能
- データが十分に増えた場合に、CNN・画像埋め込み等の利用を検討

**機械学習モデルの役割：**「この写真条件で人間が見つけやすいか」を、人間の回答データから予測すること。単に色分布を比較する処理を、学習済み予測モデルと混同しない。

## 6. 想定技術構成

| 領域 | 候補 | 役割 |
| --- | --- | --- |
| Webアプリ | Django | 画面、画像管理、クイズ、DB連携 |
| 画像合成UI | JavaScript Canvas / Konva.js | 人型の移動、拡縮、迷彩の切り替え |
| 画像処理 | Python / OpenCV / Pillow / NumPy | 色彩分析、画像生成 |
| 学習・分析 | scikit-learn / pandas | 代表色抽出、集計、将来の予測 |
| DB | SQLite → PostgreSQL | 迷彩情報、画像メタデータ、回答の保存 |
| 画像保存 | 開発時ローカル → 本番オブジェクトストレージ | 背景画像・柄画像の保存 |

※技術構成は候補。まず既存のDjangoスキルを活用してMVPを作る方針。

## 7. データモデル案

- **CamouflagePattern**：名前、説明、想定環境、画像、出典
- **BackgroundImage**：画像、環境タグ、季節、ライセンス、作成者
- **UserPatternSample**：ユーザーの迷彩写真、切り抜き領域、代表色
- **Simulation**：背景ID、迷彩ID、配置座標、サイズ、角度
- **ColorAnalysis**：背景ID、迷彩ID、分析対象領域、分析手法のバージョン、結果
- **QuizTrial**：背景ID、迷彩ID、配置条件、制限時間、出題画像
- **QuizResponse**：Trial ID、参加者識別子（必要最小限）、成功/失敗、クリック位置、応答時間、表示条件

※画像本体は原則ファイル保存、DBにはパスとメタデータを登録する。ユーザー同意・削除方針・撮影場所の個人情報（EXIFのGPS）に注意する。

## 8. 画面案

1. **トップ**：シミュレーターを使う／クイズに挑戦／迷彩図鑑を見る
2. **シミュレーター**：背景選択、迷彩選択、配置キャンバス、色彩比較
3. **迷彩詳細**：主要色、構成比、一般的な用途ラベル、比較結果
4. **マイ迷彩**：写真アップロード、領域選択、色彩分析
5. **発見クイズ**：一定時間内に対象を見つける、結果表示
6. **集計画面（後続）**：背景別・迷彩別の回答統計

## 9. 開発順序

1. **検証**：少数の背景と柄でPythonによる色分布分析を試す
2. **UI**：人型シルエットの合成・移動・拡縮・柄切り替え
3. **MVP分析**：主要色・構成比・色彩類似度
4. **アップロード**：背景画像、手持ち迷彩の写真登録
5. **クイズ**：結果取得、集計、偏りを減らす出題方式
6. **学習モデル**：人間の評価結果を用いた予測の検証

## 10. 検討中の仕様・未決定事項

- 人型素材：シルエット固定／複数ポーズのテンプレート
- 迷彩画像：撮影した布地／正規化した繰り返しパターン
- 背景画像：ユーザー投稿を含めるか、運営サンプル中心か
- 初期迷彩図鑑の掲載柄数・画像の利用許諾
- 色彩類似度の計算単位：画面全体／配置位置周辺
- クイズの制限時間と集計に必要な回答数
- 保存する回答データとユーザー認証の有無
- アプリ名

## 11. 利用上の制限

- サバイバルゲーム、画像比較、学習・視覚実験を想定する。
- 数値は画像条件に依存する参考値であり、特定環境での安全性・不可視性・実地の有効性を保証しない。
- 画像の権利を確認し、第三者の人物・私有地・撮影位置情報の取り扱いに注意する。
