# Camo Analysis（仮称）

> **状態：企画・仕様検討中／DB基盤実装済み（2026-11-20時点）**
>
> このリポジトリは、迷彩柄と背景環境の画像特徴量を比較するデータ分析プロジェクトです。PostgreSQLによる画像メタデータ管理基盤まで実装済みで、画像収集・分析は未着手です。

## プロジェクト概要

**研究目的（確定）**  
植生や背景環境によって、どの迷彩柄が人間に発見されにくいかを推定する。

**全体の研究の問い（確定）**  
背景環境と迷彩柄の色彩的な類似性は、人間による発見のしにくさに関係するのか？

**今回のMVP（確定）**  
画像解析によって、背景環境と迷彩柄の**色彩的な類似性**を定量化・可視化する。人間による発見のしにくさそのものは、この段階では測定しない。

**今後の拡張方針（確定）**  
Webクイズで人間の発見時間・正答率を収集し、画像特徴量との関係を検証する。

## 研究対象（確定）

- サバイバルゲームで実際に身を隠す自然環境を対象とする。
- フィールド全体を森林・市街地などで分類せず、実際の隠蔽場所の植生や背景を基準に分類する。
- 市街地・建造物は今回のMVPでは対象外とする。
- 背景の色彩・明暗・模様を画像特徴量として比較する。
- 人間からの発見されにくさは今回のMVPでは測定せず、将来のWebクイズで検証する。

## 研究の問い

- **RQ1（今回のMVP・確定）**：背景環境ごとに、色彩的な類似度が最も高い迷彩柄は何か？
- **RQ2（将来・確定）**：色彩的な類似度が高い迷彩柄ほど、人間に発見されにくいのか？

### 仮説（確定）

- **H1**：背景環境と色彩的に類似している迷彩柄ほど、人間による発見に時間がかかる。
- **H0**：背景環境と迷彩柄の色彩的な類似性は、人間による発見時間と関連しない。

> H1/H0の本格的な検証には、将来の人間の視覚評価データが必要です。今回のMVPの色彩比較結果のみから発見されにくさを断定しません。

## 画像収集・保存・データ管理

画像収集とデータ管理の基本方針は次のとおりです。詳細は[データ仕様書](docs/data_specification.md)を参照してください。

- 公開画像と自撮り画像を併用し、同じ背景タイプ・植生状態ごとに、できるだけ別の撮影シーンから3枚を収集する。
- 背景画像は約5mを基準とし、3〜10mを許容する。対象植生が画面の約70%以上を占める構図を基本とする。
- 原則として短辺1024px以上のJPEG / PNGを使用し、分析用画像はsRGBに統一する。
- 品質判定は `accepted` / `pending` / `rejected` の3種類とし、保留・除外理由を記録する。
- 画像はローカルに保存し、原本の `raw/` と加工済みの `processed/` を分離する。原本は上書きしない。
- 主データ管理にはPostgreSQLを採用し、画像本体ではなく識別情報、分類、出典、品質判定、ファイル情報などを管理する。

PostgreSQLの基本構成は、迷彩マスター `camouflage_patterns`、背景マスター `background_types`、画像情報 `images`、画像ファイル情報 `image_files` の4テーブルです。SQLAlchemy 2.xでモデルを定義し、Alembicで空のPostgreSQLから再現できます。原本は1画像につき1件、加工済みファイルはバージョンごとに複数件を登録できます。カラム・型・制約の詳細は[データ仕様書](docs/data_specification.md)を参照してください。

## DB開発環境の実行方法

### 1. Python環境

Python 3.12以上を使用します。

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
```

### 2. 環境変数

`.env.example` をコピーし、ローカル用の値を設定します。`.env` はGit管理対象外です。

```bash
cp .env.example .env
set -a
source .env
set +a
```

`POSTGRES_PORT` を変更する場合は、`DATABASE_URL` のポートも同じ値に変更してください。

### 3. PostgreSQL 16の起動

```bash
docker compose up -d db
docker compose ps
```

### 4. マイグレーション

```bash
alembic upgrade head
```

空のPostgreSQLから `camouflage_patterns`、`background_types`、`images`、`image_files` の4テーブルを作成します。

### 5. マスターデータのSeed

```bash
python -m camo_judge.seed
```

迷彩9種類と背景6種類を登録します。Seedは冪等で、再実行しても重複しません。

### 6. テスト

```bash
pytest
```

テストは `DATABASE_URL` のPostgreSQLサーバー上に一時DBを作成し、マイグレーション、Seed、DB制約を検証して終了時に一時DBを削除します。Docker Composeの標準ユーザーはこのテストに必要なDB作成権限を持ちます。

### 7. 停止

```bash
docker compose down
```

`docker compose down -v` はDBボリュームも削除するため、データを初期化するときだけ使用してください。
