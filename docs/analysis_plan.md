## 1. Business Understanding（課題の理解）【確定】

### 1.1 研究目的

植生や背景環境によって、どの迷彩柄が人間に発見されにくいかを推定する。

### 1.2 全体の研究の問い

背景環境と迷彩柄の色彩的な類似性は、人間による発見のしにくさに関係するのか？

### 1.3 仮説

- **H1（対立仮説）**：背景環境と色彩的に類似している迷彩柄ほど、人間による発見に時間がかかる。
- **H0（帰無仮説）**：背景環境と迷彩柄の色彩的な類似性は、人間による発見時間と関連しない。

※H0/H1の統計的検証は、人間の発見時間データを取得する後続フェーズで実施します。検定方法・有意水準・サンプルサイズは未決定です。

### 1.4 段階別の研究の問い

- **RQ1（今回のMVP）**：背景環境ごとに、色彩的な類似度が最も高い迷彩柄は何か？
- **RQ2（将来）**：色彩的な類似度が高い迷彩柄ほど、人間に発見されにくいのか？

### 1.5 今回のMVPでやること【確定】

- 迷彩・背景の画像を収集し、特徴量を数値化する。
- 色彩的な類似性を複数の背景環境で比較する。
- 比較結果を表・グラフで可視化し、限界を考察する。
- 分析手順をGitHubで再現可能な形にまとめる。

### 1.6 今回のMVPでやらないこと【確定】

- Webクイズの開発と人間の視覚評価データ収集
- 人間による発見時間・正答率の予測モデル作成
- 迷彩の実環境での発見されにくさの断定

### 1.7 研究対象【確定】

- サバイバルゲームで実際に身を隠す自然環境を対象とする。
- フィールド全体を森林・市街地などで分類せず、実際の隠蔽場所の植生や背景を基準に分類する。
- 市街地・建造物は今回のMVPでは対象外とする。
- 背景の色彩・明暗・模様を分析対象とし、MVPでは画像間の特徴量を比較する。
- 実際に人間から発見されにくいかどうかは、将来のWebクイズで検証する。

## 2. Data Understanding（データの理解）【DB基盤実装済み／分析詳細未決定】

### 2.1 データ収集規模【確定】

- 迷彩：9種類 × 1枚 = 9枚
- 背景：6タイプ × 2植生状態 × 3枚 = 36枚
- 合計：45枚
- 迷彩と背景の比較：9 × 36 = 324組

324組は独立な324サンプルではありません。同じ迷彩画像や背景画像が複数の比較に繰り返し登場します。

### 2.2 背景分類【確定】

| ID | 背景タイプ |
|---|---|
| BG01 | 笹・ササ藪 |
| BG02 | 低木・灌木の茂み |
| BG03 | 高草・ススキ |
| BG04 | シダ・低い下草 |
| BG05 | 木の根元・樹幹 |
| BG06 | ツル植物・絡み合った藪 |

各背景タイプを、画像に写っている植生状態に基づいて `green`（緑葉が多く繁茂）と `dry`（枯葉・枯草・茶色系が目立つ）に分けます。この区分は季節そのものや雨による濡れ具合を表しません。撮影年月日・季節は別のメタデータとして記録します。

### 2.3 迷彩パターン【確定】

| ID | 迷彩パターン | 分類 |
|---|---|---|
| CM01 | MultiCam Tropic | Green系 |
| CM02 | MultiCam Original | 汎用系 |
| CM03 | A-TACS FG | Green系 |
| CM04 | A-TACS AU | Dry系 |
| CM05 | Tiger Stripe（緑系） | Green系 |
| CM06 | Desert Tiger Stripe | Dry系 |
| CM07 | 陸上自衛隊迷彩2型 | 独立比較 |
| CM08 | OD（単色） | 単色比較 |
| CM09 | PenCott GreenZone | Green系 |

分類は分析用の区分であり、実測した性能評価ではありません。Tiger Stripeの具体的なバリエーションや製品は画像収集時に確定します。

### 2.4 迷彩の選定方針【確定】

1. サバイバルゲームでの知名度や使用実績があるパターンを含める。
2. Green系・Dry系の両方を比較する。
3. 同系列の異なるバリエーションを比較する。
4. 日本の森林環境を想定した比較対象として陸上自衛隊迷彩2型を含める。
5. 模様のない比較対象としてOD単色を含める。
6. 色彩だけでなく、模様の形状や細かさの違いも考慮する。

ODと柄物の比較だけでは模様単独の効果を検証できないため、因果関係は断定しません。

### 2.5 画像収集・品質・保存方針【確定】

- 公開画像と自撮り画像を併用し、同じ背景タイプ・植生状態ごとに、できるだけ別の撮影シーンから3枚を収集する。
- 公開画像と自撮り画像をメタデータで区別し、出典URL、利用条件、判明している撮影条件を記録する。不明値は推測で補完しない。
- 背景撮影は約5mを基準とし、3〜10mを許容する。カメラ高は約1.5m、原則水平・正面寄り、標準画角を優先する。
- 原則として短辺1024px以上のJPEG / PNGを使用し、分析用画像はsRGBに統一する。
- 品質判定を `accepted` / `pending` / `rejected` で管理し、保留・除外理由を記録する。
- 原本と加工済み画像を `raw/` / `processed/` に分離してローカル保存し、原本は上書きしない。

撮影条件の完全な統一よりも、一定の品質を満たしながら植生の多様性を確保するバランス重視の方針とします。

### 2.6 データ管理・DB基盤【確定・実装済み】

- 主データ管理にPostgreSQLを採用し、CSVを主たる管理方法にはしない。
- 画像本体はDBに格納せず、識別情報、分類、出典、品質判定、保存先、加工履歴などを管理する。
- `camouflage_patterns`、`background_types`、`images`、`image_files` の4テーブルを基本構成とする。
- PostgreSQL 16、SQLAlchemy 2.x、Alembicを使用し、空DBから4テーブルを再現する。
- 迷彩9種類・背景6種類は冪等なSeedで登録する。
- 背景・迷彩の分類排他、ステータス、正の撮影値、相対パス、原本1件、加工バージョン一意などをDB制約で保証する。
- 将来、画像特徴量とWebクイズの回答結果をJOINできる構成を想定する。
- 分析結果の共有・再現用にCSVエクスポートを利用できる設計とする。

### 2.7 これから決めること

- 利用する画像の具体的な出典、ライセンス、再配布・GitHub公開範囲
- 切り抜き、リサイズ、自動ホワイトバランス・彩度補正などの前処理
- ローカル画像の命名規則、バックアップ、将来のクラウド移行
- 背景3枚の集計方法とTiger Stripeの具体的なバリエーション

詳細は [データ仕様書](data_specification.md) に記載します。

## 4. Modeling（分析・モデル構築）【未確定】

MVPでは「学習器の構築」よりも**特徴量に基づく類似度計算**を行います。

- 主指標候補：HSV色分布のBhattacharyya距離（小さいほど類似）
- 副指標候補：主要色の構成比、平均明度差、明度標準偏差の差、代表色のΔE00、エッジ密度の差
- 背景タイプと植生状態の組み合わせごとに3枚の背景画像を集計し、迷彩別の比較を行う

**決定待ち**：主・副指標の確定、距離の計算条件、外れ値・ばらつきの扱い、集計ルール。

指標の定義は [特徴量・比較仕様書](feature_specification.md) に記載します。

## 9. 注意・制約

- 色の類似度は、発見のしにくさの代理指標候補であり、視認性そのものではありません。
- 迷彩布の接写と遠景の背景画像を比較すると、模様のスケールが一致しない場合があります。
- 撮影条件・色補正・ディスプレイ環境は結果に影響し得ます。
- 各迷彩1枚では、そのパターンの代表性や再現性に制約があります。
